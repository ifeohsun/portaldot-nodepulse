NodePulse

Health monitoring for Portaldot nodes
with verifiable on-chain uptime attestations

Portaldot Hacker House · Track: Node Operations & Tooling

github.com/ifeohsun/portaldot-nodepulse

1/7

Problem

  • Node operators and dApps can't easily tell if a Portaldot RPC / validator node is healthy
  • Uptime claims are self-reported and unverifiable
  • Outages are discovered by users, not by operators
  • No shared, public record of node health on Portaldot
2/7

Solution

  • Monitor Substrate + EVM JSON-RPC: peers, sync, block lag, latency → 0–100 health score
  • JSONL history, uptime stats, watch loop, degrade/recover alerts (Discord webhooks)
  • NodePulseRegistry contract: operators register nodes and post signed report() attestations
  • Backend-free live dashboard reads PulseReported events straight from testnet RPC
3/7

Architecture

  Portaldot node (Substrate + EVM RPC)
              │  probes: peers · sync · lag · latency
              ▼
  nodepulse.monitor ──► score 0–100 ──► history.jsonl ──► alerts (webhook)
              │
              ▼  attest.py: keyless ABI calldata (register / report)
  operator signer ──► NodePulseRegistry (chain 420420777)
                              │  PulseReported events (eth_getLogs)
              ┌───────────────┴───────────────┐
              ▼                               ▼
   nodepulse.status / events          Live dashboard (GitHub Pages)
